# satisfactory-analyzer

Reads a Satisfactory `.sav` and tells you what is in it: where you are in the tech tree, every building and what it is making, belts, power, every item in every box, and, given a folder of saves, the order everything happened in. The same tool as `sl2-analyzer`, for a different game: a Python CLI and a browser app that share one reading logic.

```
python3 sat_to_md.py                                  # newest save it can find on this machine
python3 sat_to_md.py world.sav -o world.md            # Markdown
python3 sat_to_md.py world.sav -o world.json          # JSON, against schema.json
python3 sat_to_md.py saves/ -o history.md             # COMBINED: runs, branches, journey charts, first-appearance tables
python3 -m http.server 8777 --bind 127.0.0.1         # then open http://127.0.0.1:8777/ : the web app, parses in the tab, uploads nothing
```

Python needs nothing beyond the standard library. The web app needs a browser with `DecompressionStream` (anything current) and nothing else; Mermaid for the combined charts is vendored.

## What "reads everything" means

Every object's property list is decoded, and so is the class-specific data after it (belt contents, power lines, vehicles, drones, lightweight buildables). The report's last line says how much it could not decode: unread properties, undecoded bytes, object errors. On every world save on the author's machine (save versions 46, 51, 52 and 60, about 90 files) all three are zero, and `tests/test_saves.py` keeps it that way. A save that trips any of them says so in its own report rather than printing a number it could not verify.

## Layout

- `sav/` the Python reader: `reader.py` (header, chunks, level tables), `props.py` (properties, structs, class data), `model.py` (the one summary every writer shares), `render.py`, `combine.py`, `names.py`.
- `app/` the same logic in JavaScript, plus `view.js` (DOM cards), `mdview.js` (Markdown to DOM, never innerHTML), `main.js`, `worker.js`.
- `tools/parity.mjs` the correctness gate: runs both readers over the same saves and demands identical summaries, identical Markdown, and an identical combined document.
- `schema.json` the JSON contract, generated by `tools/gen_schema.py`.
- `notes/format.md` the file format as implemented.

## Limits

Names are derived from class paths (`Desc_IronPlateReinforced_C` becomes "Reinforced Iron Plate") with a small override table, because the game's own display names live in encrypted paks. Resource-node purity is not stored per node in the save, so it is not reported. Power figures are the summed per-machine target draw, not the live grid load, and the report says so.
