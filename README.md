# satisfactory-analyzer

**Read a Satisfactory `.sav` and get back a plain report of the factory: where you are in the tech tree, every building and what it is making, and what is in every box. Browser or command line.**

A Satisfactory save is a few thousand compressed objects, and the game never adds them up for you. I wanted the total: where I am in the tech tree, how many buildings I have, what each machine is making, what is in every box. This prints it. Give it a folder of saves and it prints the history instead, in the order things happened.

## Use it

```
python3 sat_to_md.py                                  # the newest save it can find on this machine
python3 sat_to_md.py world.sav -o world.md            # Markdown
python3 sat_to_md.py world.sav -o world.json          # JSON, against schema.json
python3 sat_to_md.py saves/ -o history.md             # a whole folder: runs, branches, journey charts, first-appearance tables
python3 -m http.server 8777 --bind 127.0.0.1         # then open http://127.0.0.1:8777/ for the web app
```

The Python side is the standard library. The web app wants a browser with `DecompressionStream`, which is anything current. Mermaid, for the charts in the combined view, is vendored.

## How far it reads

Every property in the file gets decoded, and so does the class data after them: belt contents, power lines, vehicles, drones, foundations and walls. The last line of every report counts what did not decode. On all of my saves (about 90 files, save versions 46, 51, 52 and 60) that count is zero, and `tests/test_saves.py` fails if it ever stops being zero.

## What it can't tell you

- **Resource-node purity.** The save never stores it.
- **Live power load.** The report sums each machine's target draw and labels it as that.
- **Names for creatures, research trees and integrated buildings.** Everything else comes from the Docs file the game ships (`db_sat/names.json`, built with `tools/gamefiles.py`), so `BP_EquipmentDescriptorShockShank_C` shows as the Xeno-Zapper. The classes that file lacks get their class name made readable, with a small override table in `sav/names.py` and `app/names.js`.

## Layout

- `sav/` is the Python reader: `reader.py` (header, chunks, level tables), `props.py` (properties, structs, class data), `model.py` (the one summary every writer shares), `render.py`, `combine.py`, `names.py`.
- `app/` is the same logic in JavaScript, plus `view.js` (the DOM cards), `mdview.js` (Markdown to DOM, never innerHTML), `main.js` and `worker.js`.
- `schema.json` is the JSON contract, generated by `tools/gen_schema.py`.
- `notes/format.md` is the file format as implemented.

## Two readers, one answer

The browser port is checked against the Python reader byte for byte. `tools/parity.mjs` runs both over the same saves and fails on any difference in the summary, the Markdown or the combined document. A port drifts silently otherwise.
